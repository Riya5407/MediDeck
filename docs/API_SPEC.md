# MediDesk API Specification

Internal pharmacy management API. FastAPI + psycopg (raw SQL, no ORM). No authentication.
Base path: `/api`. All bodies and responses are JSON. Field names match database column names (snake_case).

## 1. Global rules

**Config (env, never hardcoded):** `DATABASE_URL`, `LOW_STOCK_THRESHOLD=20`, `EXPIRY_WARNING_DAYS=30`, `PAYMENT_MODES=Cash,Card,UPI`, `CORS_ORIGINS`.

**Dates:** ISO `YYYY-MM-DD`. "Today" is the server date.

**Pagination (list endpoints):** `?page=1&page_size=20` (max 100). Response:
`{ "items": [...], "total": 123, "page": 1, "page_size": 20 }`

**Errors:** always `{ "detail": "human readable message" }`. Mapping from PostgreSQL:

| Cause | HTTP | Notes |
|---|---|---|
| Trigger `RAISE EXCEPTION` (P0001) | 400 | Pass the trigger's message through unchanged, e.g. "Insufficient stock in batch 12" |
| Check violation (23514) | 400 | Friendly message naming the field |
| Foreign key violation on delete (23503) | 409 | "Cannot delete: this record is in use" |
| Unique violation (23505) | 409 | "Already exists" |
| Row not found | 404 | |
| Request validation | 422 | FastAPI default shape is fine |

**Every write that touches more than one table runs in a single transaction.** IDs are generated by the database (identity columns); the API never supplies them.

**Derived statuses (computed in SQL, never stored):**
- Batch `status`, first match wins: `expired` (exp_date < today), `out_of_stock` (qty_in_stock = 0), `expiring_soon` (exp_date <= today + EXPIRY_WARNING_DAYS), `low_stock` (qty_in_stock <= LOW_STOCK_THRESHOLD), else `in_stock`.
- Medicine `status` uses `total_stock` = sum of qty_in_stock over non-expired batches: `out_of_stock` (0), `low_stock` (<= LOW_STOCK_THRESHOLD), else `in_stock`.

## 4. Medicines

**Medicine object:** `{ med_no, med_name, category, manufacturer, unit, mrp, total_stock, status, nearest_expiry }`
(`nearest_expiry` = earliest exp_date among batches with stock, or null.)

| Method | Path | Notes |
|---|---|---|
| GET | `/medicines` | Query: `search` (name/manufacturer, case-insensitive), `category`, `status`, `page`, `page_size`. Paginated |
| GET | `/medicines/{med_no}` | Medicine object plus `batches: [Batch]` |
| POST | `/medicines` | Body: `{ med_name (required), category, manufacturer, unit, mrp }` -> 201 + Medicine |
| PUT | `/medicines/{med_no}` | Same body as POST |
| DELETE | `/medicines/{med_no}` | 409 if batches, sales, orders or prescriptions reference it |

## 5. Batches

**Batch object:** `{ batch_no, med_no, med_name, mfg_date, exp_date, qty_in_stock, pur_price, status, days_to_expiry }`
(`days_to_expiry` is negative when expired.)

| Method | Path | Notes |
|---|---|---|
| GET | `/batches` | Query: `search` (medicine name), `status` (any batch status), `med_no`, `page`, `page_size`. Paginated, soonest expiry first. Also returns `counts: { total, expired, expiring_soon, valid }` for the summary cards |
| POST | `/batches` | Body: `{ med_no, mfg_date, exp_date, qty_in_stock, pur_price }` |
| PUT | `/batches/{batch_no}` | Same body |
| DELETE | `/batches/{batch_no}` | 409 if sold from |

## 6. Point of sale and sales

**POS search**

`GET /pos/medicines?q=para&limit=20` returns
`[{ med_no, med_name, unit, mrp, total_stock, batches: [{ batch_no, exp_date, qty_in_stock }] }]`
Only sellable batches are included (exp_date >= today and qty_in_stock > 0), ordered by `exp_date` ascending so the oldest stock sells first. Medicines with no sellable batch are omitted.

**Create bill**

`POST /sales` body:
```json
{
  "cust_no": 5,
  "emp_no": 2,
  "payment_mode": "Cash",
  "lines": [
    { "med_no": 1, "batch_no": 10, "qty_sold": 2, "sale_price": 12.5 }
  ]
}
```
- `cust_no` may be null (walk-in). `emp_no` and `payment_mode` required. `payment_mode` must be one of `/meta` payment_modes.
- `sale_price` optional; omitted means the trigger defaults it to the medicine MRP. A lower price is a discount.
- At least one line. The same `batch_no` may not appear twice in one bill (primary key) -> 400.
- Insert into `sale` (sale_date = today), then each line into `sale_details`, in one transaction. The database triggers reduce stock and calculate `total_amt`. Do not calculate or write stock or the total in application code.
- Returns 201 + Sale detail.

**Sale detail object:**
`{ bill_no, sale_date, cust_no, cust_name, emp_no, emp_name, payment_mode, total_amt, lines: [{ med_no, med_name, batch_no, qty_sold, sale_price, mrp, discount_pct, line_total }] }`
(`discount_pct` = (mrp - sale_price) / mrp * 100, rounded to 2 places.)

| Method | Path | Notes |
|---|---|---|
| GET | `/sales` | Query: `from`, `to`, `search` (bill number or customer name), `page`, `page_size`. Items: `{ bill_no, sale_date, cust_name, emp_name, payment_mode, total_amt, item_count }`, newest first |
| GET | `/sales/{bill_no}` | Sale detail |
| DELETE | `/sales/{bill_no}` | Cancels the bill: delete its lines first (triggers restore stock), then the sale, in one transaction |

Bills are not editable after creation; to correct one, cancel and re-create.

## 9. Purchase orders

**Purchase order object:** `{ pur_no, sup_no, sup_name, order_date, status, total, lines: [{ med_no, med_name, qty_ordered, rate, line_total }] }`
(`total` = sum of qty_ordered * rate. Status is one of Pending, Delivered, Cancelled.)

| Method | Path | Notes |
|---|---|---|
| GET | `/purchase-orders` | Query: `status`, `sup_no`, `from`, `to`, `page`, `page_size`. Items without `lines`, newest first |
| GET | `/purchase-orders/{pur_no}` | Full object |
| POST | `/purchase-orders` | Body: `{ sup_no, lines: [{ med_no, qty_ordered, rate }] }`. Creates with status `Pending`, order_date today |
| PATCH | `/purchase-orders/{pur_no}/status` | Body: `{ "status": "Cancelled" }`. Only allowed from `Pending`, otherwise 400 |
| POST | `/purchase-orders/{pur_no}/receive` | See below |

**Receive order** body:
```json
{
  "lines": [
    { "med_no": 1, "mfg_date": "2026-09-01", "exp_date": "2028-09-01", "qty_received": 100 }
  ]
}
```
- Order must be `Pending`, else 400. Every med_no of the order must appear exactly once.
- `qty_received` optional, defaults to `qty_ordered`.
- In one transaction: insert one `medicine_batch` per line (`qty_in_stock` = qty_received, `pur_price` = the order's `rate`), then set status to `Delivered`.
- Returns the updated Purchase order object plus `created_batches: [batch_no]`.

## 10. Prescriptions

**Prescription object:** `{ pres_no, cust_no, cust_name, doc_name, pres_date, diagnosis, items: [{ med_no, med_name, dosage, duration }] }`

| Method | Path | Notes |
|---|---|---|
| GET | `/prescriptions` | Query: `cust_no`, `search` (doctor or customer), `from`, `to`, paginated. List items omit `items` and include `item_count` |
| GET | `/prescriptions/{pres_no}` | Full object |
| POST | `/prescriptions` | Body: `{ cust_no, doc_name, pres_date, diagnosis, items: [{ med_no, dosage, duration }] }`. Header then items, one transaction |
| PUT | `/prescriptions/{pres_no}` | Same body. Replaces the full item list |
| DELETE | `/prescriptions/{pres_no}` | Deletes items first |

Prescriptions are records only; they do not create bills or reduce stock.

| POST | `/employees` | Body: `{ emp_name (required), emp_role, salary, phone_no }` |

## 12. Reports

All accept `from` and `to` (default: last 30 days) where relevant.

| Method | Path | Response |
|---|---|---|
| GET | `/reports/sales-by-date` | `[{ date, bills, total }]` |
| GET | `/reports/top-medicines?limit=10` | `[{ med_no, med_name, qty_sold, revenue }]` |
| GET | `/reports/expired-stock` | `{ items: [Batch with value], total_value }` where value = qty_in_stock * pur_price, for batches with exp_date < today and qty > 0 |
| GET | `/reports/purchases-by-supplier` | `[{ sup_no, sup_name, orders, total }]` (cancelled orders excluded) |

Each report also supports `?format=csv` for export.
